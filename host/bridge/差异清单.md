# esp-sdr-bridge 差异清单（可复用 / 需替换 / 需新增）

> 步骤 0 产物。目标：ESP32-C5（ESP-SDR 三模式固件）+ `monitor_gui` 的既有能力不变，
> 新增一个 RTL-TCP 桥接，让本地 SDR# 以 **RTL-SDR (TCP)** 接入 `127.0.0.1:1234`。
> 结论先行：**RTL-TCP 服务端与控制命令层可原样复用；样本来源层必须整体重写；DDC/抽取层直接丢弃。**
> 另有一个必须在动手前拍板的阻塞点（见 §5.1：SDR# 最低只提供 0.25 MSPS，而 C5 最高 80 kS/s）。

参考源码：`esp-sdr-bridge/src/esp_sdr_bridge/bridge.py`（303 行，单文件，行号均指该文件）。

## 3. C5 固件侧实测能力（本机 COM10 查询）

| 命令 | 实测回复 | 对桥接的含义 |
| --- | --- | --- |
| `INFO` | `C5SDR 6 burst 16380` | 家族/协议版本 6 |
| `RANGE?` | `RANGE 100 6000 1` | 100–6000 MHz，**步进 1 MHz** |
| `LIMITS?` | `gain:[0,80,1]`、`bandwidth:[11,48,1,0]`、`rates:[80M,40M,20M,10M,8M,4M]`、`bits:[8,10]` | 增益 0..80；带宽 0=Open 或 11–48 MHz；`rates` 是**快照**档位，不是 IQS 档位 |
| `GAIN?` | `GAIN HARDWARE -1 0 80 0` | 默认硬件 AGC，手动 0..80 |
| `CAPS` | `… RXLIMITS GAIN HWAGC IQ8 SERIALLEASE TUNEEXT MON WIFIMON BLEMON …` | 有 `MON`/`IQ8` |
| `TRANSPORT?` | `TRANSPORT USB 0` | C5 只有 USB-Serial-JTAG（UART0 已关闭） |

IQS（连续流，桥接要用的那条）：

- `IQS ON <rate>`：rate 必须整除 240 MHz 与 80 MHz，范围 10000–80000 →
  可用档 **10k / 20k / 25k / 40k / 50k / 80k**。
- 帧格式：`IQFRAME <len> <rate> <crc32>\n` + `len` 字节 **int32 LE 交错 I/Q**；
  当前每块 128 对（1024 B），但**不得假定块长**（按 `len` 解析）。
- CRC32 = zlib 多项式，**只覆盖载荷**（不含文本头）。
- 无样本序号 → 连续性只能靠“块长是否等于 128 对”“rate 字段是否变化”“CRC 是否通过”判断；
  丢帧表现为帧数缺口，可用 `IQS?` 的 `dropped` 与桥接侧计数对照。
- 背压语义（已在固件侧修好）：主机不读时固件丢帧并计数，**不会**阻塞命令通道；
  但被丢掉的那一帧可能是**截断的**，桥接必须能从中恢复（按下一个 `IQFRAME` 头重同步）。
- 满量程：载荷是基带 boxcar 累加值（相对 ADC 码值缩放 2^-6），**没有公开的满量程定义**。
  实测 40 kS/s 时 `|x|` 的 99 分位 ≈ 6.9e4，峰值可达 1.8e5。

租约语义（桥接必须遵守）：`SYNC <nonce>` 拿会话 → 5 s 无命令自动释放；
期间其它端口的命令回 `ERR busy`。桥接启动流程建议：
`RELEASE` → `SYNC <nonce>` → `MON?`（要求 `WIFI:off BLE:off IQ:off`）→ `FREQ`/`BANDWIDTH` →
`IQS ON <rate>`；退出 / SDR# 断开 → `IQS OFF` → `RELEASE`。

## 4. SDR# 侧事实（为验收自动化摸底）

- 可执行文件：`SDR#/sdrsharp-x86-noskin/SDRSharp.exe`（v1.0.0.1716）；
  另有 `SDR#/sdrsharp-plutosdr-0.5.4/`（本次不用）。
- **不支持命令行参数**指定源/地址（bin 里没有 `/config`、`config:` 之类入口；
  只有 `ConfigurationManager` = .NET 自身的 AppSettings）。
- 源的选择与 RTL-TCP 地址存在 `SDRSharp.exe.Config` 的 `appSettings` 里：
  - `iqSource`：下拉框索引。**实测 `5` = `RTL-SDR (TCP)`**
    （`FrontEnds.xml` 里它是第 4 项，索引有 +2 偏移；`12` = PlutoSDR）。
  - `RTLTcpHost` / `RTLTcpPort`：`SDRSharp.RTLTCP.dll` 持久化的键（已写入 `127.0.0.1` / `1234`）。
  - 原配置已备份为 `SDRSharp.exe.Config.bak`；当前已把 `iqSource=5` + 两个 RTLTCP 键写好。
- **启动后不会自动开始流**：必须点工具栏 ▶（或 Stop 后再 Start）。实测：
  预置好 config 启动 SDR#，14 s 内监听 1234 端口**没有**任何连接。
- SDR# 的 RTL-TCP 插件硬编码了采样率列表（从 `SDRSharp.RTLTCP.dll` 抽出的 UTF-16 字符串）：
  **0.25 / 0.900001 / 1.024 / 1.4 / 1.8 / 1.92 / 2.048 / 2.4 / 2.8 / 3.2 MSPS**。
- 它会发的命令（DLL 里的符号已确认）：`CMD_SET_FREQ(0x01)`、`CMD_SET_SAMPLE_RATE(0x02)`、
  `CMD_SET_AGC_MODE(0x03)`、`CMD_SET_GAIN(0x04)`、`CMD_SET_FREQ_COR(0x05)`、
  `CMD_SET_TUNER_GAIN_INDEX(0x0d)`。与我们已有解析一致。
- 头部用的 tuner type / gain count 决定了 SDR# 的增益滑条档数：填 `5` + `29`。

**结论（自动化）**：8.1/8.2 无法只靠配置文件完成“开始流”，需要**一次人工点击 ▶**；
其余（头部、命令响应、流格式、回退、断开释放、30 s 连续）都能脚本化：
- `tools→bridge/verify_rtl_tcp.py`：扮演严格 rtl_tcp 客户端，逐项断言（覆盖判据 6 与 8.3/8.4/8.5）；
- SDR# 侧用“预置 config + 人工 ▶ + 桥接日志（客户端连接、字节速率、FREQ 回执）”作为判据。

## 5. 关键差异与需拍板的决策

### 5.1 【阻塞】SDR# 最低 0.25 MSPS vs C5 最高 80 kS/s

SDR# 只能选 0.25 MSPS 以上；若桥接只按固件真实速率（≤80 kS/s）出流，
SDR# 会以 250 kS/s 消费 → 缓冲持续欠载 → 不出图/卡顿。三种做法：

| 方案 | 做法 | 结果 | 代价 |
| --- | --- | --- | --- |
| A（推荐） | 固件仍 80 kS/s；主机侧**线性插值上采样**到 SDR# 请求的速率 | SDR# 稳定出图；真实内容只占中心 ±40 kHz（几何上正确），README 明示 | 少量插值镜像/带内倾斜；CPU 很低（80k→250k 才 3.1×） |
| B | 零阶保持上采样 | 同上，但镜像更明显、频谱上会出现“梳状” | 更简单，图像差 |
| C | 不上采样，强行 80 kS/s 出流 | SDR# 欠载、几乎不可用 | 不满足判据 1/3 |

> 注意：判据 2.5 写的是“不支持的速率回退最近可用值并记日志”，与“上采样”并不矛盾——
> 回退决定**串口侧**用哪档，上采样只是让 SDR# 的消费速率对得上。若您只想严格按“回退”语义，
> 我会把上采样做成默认关闭（`--upsample` 显式开启），但那样 SDR# 基本看不到频谱。

### 5.2 频率粒度 1 MHz

C5 的 `FREQ` 只到整 MHz（无 FOFS），所以 SDR# 里拖动 500 kHz 可能无变化（取整后相同）。
建议：日志打印 `requested=1234.567 MHz → FREQ 1235 MHz (Δ=+0.433)`，README 写清；
若需要 kHz 级，需**新增固件命令**（例如给 C5 加 FOFS 等价的 PLL 偏移），属于“新增能力”，
需要您点头——本次默认不做。

### 5.3 增益映射

`0x0d`（0..28 索引）→ C5 `GAIN MANUAL round(idx/28*80)`；
`0x04`（0.1 dB，R820T 列表 0..496）→ C5 `GAIN MANUAL round(v/496*80)`；
`0x03 = 1` → `GAIN HARDWARE`（AGC），`0x03 = 0` → 恢复手动。
C5 增益索引是 PHY 表项、不是 dB，故 README 声明“增益未按 dB 标定”。

### 5.4 满量程 / 校准

int32 → uint8 的参考值：默认 `--full-scale auto`（启动后前 ~0.5 s 的 `|x|` 99 分位）
或固定值；映射 `u = clip(128 + k*(x - dc)/ref, 0, 255)`，`k≈100` 留 2 bit 余量。
**README 必须写明“幅度未校准”**——C5 侧没有可追溯的满量程定义。

### 5.5 连续性检查

无样本序号，只能：
① CRC32 失败计数；② 块长 ≠ 128 对（被截断）计数；③ `rate` 字段变化 = 重新协商；
④ 与 `IQS?` 的 `dropped` 对账。任何异常**只记日志并继续**，不中断 TCP、不重开串口。

## 8. 最终落地（按确认结果：**只做 PlutoSDR / libiio 路线**）

> 决策记录：原任务书写的是 RTL-TCP；§7 确认时选择了「只做 PlutoSDR」，
> 因此 rtl_tcp 服务端与 12 字节头等内容**不落地**，`rtl_tcp` 的 8 条验收
> 相应替换为 PlutoSDR 版（见 `README.md` §9）。

### 8.1 复用了什么（与硬件无关的部分）

| 复用内容 | 来源 | 在 `pluto_iiod.py` 中的位置 |
| --- | --- | --- |
| 「设备线程产出复数样本 → 各客户端 sink 分发」的架构 | `bridge.py` `Sinks`（L33-44）+ `Tx` 发送线程（L152-178） | 简化为 `Stream`（单客户端、带去重采样与背压丢弃），多连接只做控制/数据两条 |
| 残余直流用 EMA 估计后减去 | `Device.run()` L116-117 | `C5Device._take_frame()` 里的 `self._dc` |
| `--fake` 合成源（单音 + 噪声） | `Fake` L121-134 | `FakeDevice` |
| 采样率回退到最近可用档 + 记日志的思路 | `Device.set()` L57-61 `min(RATES, key=...)` | `nearest_rate()` / `C5Device.set_rate()` |

### 8.2 替换/丢弃了什么

| 原实现 | 处置 | 原因 |
| --- | --- | --- |
| `Device`（S3：2 Mbaud 串口 + `IQS 0 <dec> <bits> <code> <shift> <mode>` + 24 B `IQS1` 头 + 64 位样本序号） | **整体重写** 为 `C5Device` | C5 是 USB-Serial-JTAG + 文本头 `IQFRAME <len> <rate> <crc32>` + int32 LE 载荷，且**没有样本序号**，只能靠块长/CRC/`IQS?` 对账 |
| 双级 FIR DDC、`fs/4` IF、`dec/bits/shift` | **丢弃** | C5 无 DDC、单核；抽取只在固件 IQS 内部发生 |
| `out_shift()` 数字增益、`S3_GAIN` 查表 | **丢弃** | 换成 C5 的 `GAIN MANUAL 0..80`（PHY 表项，不是 dB） |
| `FREQ+FOFS` 组合（kHz 级） | **替换** | C5 只有整 MHz；换频需先 `IQS OFF` 再 `FREQ` 再 `IQS ON` |
| SpyServer 全套（~110 行） | **丢弃** | 范围外 |
| rtl_tcp 服务端（L243-267）与 12 B 头 | **丢弃**（本次不落地） | 按 §7 决策改走 PlutoSDR；其中「命令→设备」的映射思路保留在 iiod 属性写入里 |

### 8.3 新增了什么

1. `pluto_iiod.py`：iiod 文本协议子集（`VERSION/PRINT/TIMEOUT/OPEN/CLOSE/READ/WRITE/READBUF/EXIT`），
   以及一个能让 SDR# 认成 Pluto 的 IIO XML（`ad9361-phy` + `cf-ad9361-lpc`，含
   `altvoltage0.frequency`、`voltage0.{sampling_frequency,rf_bandwidth,hardwaregain,gain_control_mode}`，
   通道属性一律带 `filename="in_/out_..."`，否则本地 libiio 认为只读）。
2. 串口侧的单线程命令通道（`_pending` + 帧/文本分流 `_pump`）：Windows 上两个线程并发读
   同一个 CDC 口会直接 `ERROR_BAD_COMMAND`，且帧扫描会把 `OK` 吞掉。
3. 空闲即释放：没有客户端时 `IQS OFF + RELEASE` 并**关闭串口**，让 `monitor_gui` 能接管。
4. `dev/Probe.exe`（C#，链接 SDR# 自带的 `libiio-sharp.dll`）：不启动 SDR# 也能断言整条协议链。

### 8.4 与 SDR# 的实测对照

| 项 | 结果 |
| --- | --- |
| `iqSource` 取值 | 实测 **12 = PlutoSDR**（`5 = RTL-SDR (TCP)`），源下拉索引与 `FrontEnds.xml` 有 +2 偏移 |
| URI 配置键 | `PlutoSDRURI`（`ip:127.0.0.1`），端口固定 30431；已写入 `SDRSharp.exe.Config`，原文件备份为 `.bak` |
